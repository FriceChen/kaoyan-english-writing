# 机制

> 这个文件只解决一个问题：
>
> **为什么会这样？中间到底发生了什么？**
>
> 机制不是一个原因词，而是一段过程。

---

## 一、什么时候值得看机制

适合：

- 已经知道现象，但不知道为什么；
- A 到 B 中间缺了一步；
- 自己写出了一个判断，但感觉只是结论；
- 已经知道 A 与 B 是什么关系，但不知道这种关系怎么产生；
- 已经发现哪里断了，但不知道为什么会断；
- 一个观点需要真正的因果 / 过程支撑。

不适合：

- 只是缺某个话题事实 → `02_素材`；
- 中文逻辑已经完整，只是不会英语 → `03_表达`；
- 材料本身已经够写；
- 为了“高级”硬找机制；
- 你还没判断清楚现象、关系或失灵 → 先回 `01_看材料` / `02_判关系` / `04_找失灵`。

先看 `00_怎么用.md`：够写就写。

---

## 二、机制是什么

### 不是原因词，是过程

不要写：

```text
原因一：科技
原因二：社会
原因三：个人
```

要写：

```text
A
↓
中间发生了什么
↓
B
```

例子：

- 弱：科技发展导致人际关系疏远。
- 强：沟通成本下降 → 联系范围扩大 → 稳定关系仍需要共同经历和长期互助 → 联系更多，不等于关系更深。

前者是“原因词 + 结论”，后者才是机制。

### 一条链胜过一张清单

> **1 条讲清楚 > 4 条点到为止。**

列四个“原因”，通常不如把一条链写透。

### 机制必须有中间过程

如果只是：

> A causes B

还不算真正解释。继续问：

> **中间发生了什么？**

### 机制不能超过材料支持

材料只显示“同时发生”，就不要写“导致”。

这条边界和 `01_看材料.md` 的 Evidence Ceiling 相同：**解释力度不能超过材料真正支持的程度。**

材料弱时，可以写成合理解释，但不要伪装成事实。

## 三、症状 → 机制：快速入口

不需要背 25 个名字。先看自己遇到的是哪种“解释不通”。

| 我现在发现的问题 | 优先看哪个家族 |
|---|---|
| 有资源，但没有结果 | 四、东西明明有了，为什么没有变成结果？ |
| 工具越来越强，人反而不会了 | 三、能力是怎么形成，又怎么被削弱的？ |
| 每个人都更努力，整体却没改善 | 七、为什么大家都更努力，结果却越来越卷？ |
| 指标很好看，真实目标没实现 | 五、数字变好了，实际目标真的变好了吗？ |
| 某方案对一部分人有效，对另一部分人无效 | 八、为什么同样的东西换个人或场景就失效？ |
| 短期很好，长期出现代价 | 九、事情接下来会怎么变？ |
| 一方获益，另一方承担成本 | 六、好处和代价落在谁身上？ |
| A 增加以后 B 被挤掉 | 一、资源有限，怎么分？ |
| 两个东西看起来在竞争，实际可能互相配合 | 二、两个东西是替代、互补，还是放大差距？ |
| 一个东西本来合理，过了某个点却开始有害 | 九、事情接下来会怎么变？ + `06_换个角度看.md` 的“边界” |

这张表只是入口。找到家族后，再往下看具体机制。

## 四、九个机制家族

> 旧体系口称“26 条机制”；正文实际有 25 个机制标题，其中 `Erosion / Dependency` 含两个侧面（侵蚀 / 依赖）。按最保守口径，25 个标题全部保留；把这两个侧面分开计，就是旧说的 26 条。
>
> 下面不恢复 M1–M26 编号；英文名称只作检索标签。

### 家族一：资源有限，怎么分？

**它在解释什么：**
当资源有限时，一个东西的增加，会让另一个东西得到更少。

**最基本的过程链：**

```text
有限资源
→ 更多资源流向 A
→ B 得到的资源减少
→ B 被挤压
```

**属于这一家的旧机制：**

- **Crowding Out｜挤占**：A 占用有限资源，挤掉 B。资源可以是时间、注意力、金钱、精力、认知容量。
- **Opportunity Cost｜机会成本**：选择 A，就放弃了 B；被放弃的选项本身有成本。

**什么时候有用 / 不要硬套：**

- 有用：时间分配、注意力竞争、预算、工作与休闲、学习与兼职。
- 不要硬套：如果没有明确的“有限资源”，就不要说挤占；如果两个东西可以同时增加，也不一定是挤占。

---

### 家族二：两个东西是替代、互补，还是放大差距？

**它在解释什么：**
A 和 B 不一定是“谁好谁坏”，也可能是替代、互补，或者同一个工具对不同人产生不同放大效果。

**最基本的过程链：**

```text
替代：A ↑ → 接管 B 的功能 → B 的作用 ↓
互补：A + B → 比单独使用更好
放大：原有能力 × 工具 → 差距被放大
```

**属于这一家的旧机制：**

- **Substitution｜替代**：A 增加，B 的功能被部分或完全接管。关键不是“替代多少”，而是“替代了什么”：低价值负担，还是核心能力 / 目标。
- **Complementarity｜互补**：A 和 B 各自承担不同功能，合起来比单独用更好。
- **Amplification｜放大**：工具不创造能力，而是放大原有差异；同样的工具，对已经有能力的人帮助更大。

**什么时候有用 / 不要硬套：**

- 有用：AI 与人的能力、线上与线下、理论与实践的配合、技术对不同人群的影响。
- 不要硬套：如果两者没有功能关系，只是同时出现，就不要说替代或互补。
- 不要把“替代”自动写成“坏事”；替代低价值负担可能是合理的。

---

### 家族三：能力是怎么形成，又怎么被削弱的？

**它在解释什么：**
能力通常不是“拿到结果”形成的，而是在练习、犯错、反馈、调整中形成的；如果帮助绕过了这个过程，能力可能被削弱。

**最基本的过程链：**

```text
练习 → 失败 → 反馈 → 调整 → 能力

帮助 → 直接给结果 → 练习过程被绕过 → 能力形成被削弱
```

**属于这一家的旧机制：**

- **Capability Formation｜能力形成**：能力来自反复的尝试、失败、反馈和调整，不是来自得到答案。
- **Erosion / Dependency｜侵蚀 / 依赖**：外部帮助给出结果，但绕过了练习过程，长期形成依赖，能力反而退化。

**什么时候有用 / 不要硬套：**

- 有用：教育、AI 辅助、父母过度帮助、技能训练、运动、独立思考。
- 不要硬套：不是所有帮助都削弱能力；关键是它承担的是低价值步骤，还是能力形成所需的核心练习。
- 不要把所有“变方便”都写成“能力退化”。

---

### 家族四：东西明明有了，为什么没有变成结果？

**它在解释什么：**
资源、服务、政策、技术存在，不等于目标自动实现；中间需要转化条件。

**最基本的过程链：**

```text
输入 / 资源
→ 中间条件
→ 有效使用
→ 结果
```

**属于这一家的旧机制：**

- **Conversion｜转化**：X 存在，但不会自动变成 Y；中间缺了转化环节。
- **Bottleneck｜瓶颈**：链条上有一个环节卡住，继续增加前面的投入也无效。

**什么时候有用 / 不要硬套：**

- 有用：教育资源、数字服务、医疗、公共设施、政策落地。
- 不要硬套：如果结果其实已经发生，就不要说“转化失败”。
- 如果问题是“东西不够”，那是能力 / 资源不足，不是转化失败；可以看家族八。

> 如果你还没判断“哪里断了”，先回 `04_找失灵.md` 的五步；这里只解释“为什么会断”。

---

### 家族五：数字变好了，实际目标真的变好了吗？

**它在解释什么：**
指标本来只是目标的近似，但一旦奖励绑定指标，人们可能优化指标本身，而不是优化目标。

**最基本的过程链：**

```text
指标绑定奖励
→ 人们优化指标
→ 行为适应指标
→ 指标上升
→ 真实目标未必改善
```

**属于这一家的旧机制：**

- **Decoupling｜脱钩**：指标上升，但实质没有同步上升。
- **Gaming｜指标博弈**：奖励绑定指标后，人们针对指标本身采取行动，目标反而被放在一边。它常是脱钩的生成方式。

**什么时候有用 / 不要硬套：**

- 有用：分数、KPI、论文数量、打卡、形式主义、排名。
- 不要硬套：如果指标本身就是目标（例如“就是要提高这个数字”），就不一定是脱钩。
- 不要把所有测量都写成“指标害人”；测量本身是必要的，问题是 proxy 取代了目的。

---

### 家族六：好处和代价落在谁身上？

**它在解释什么：**
一个选择看起来合理，可能因为收益归自己，成本却由别人、社会、环境或未来承担。

**最基本的过程链：**

```text
收益 → 决策者
成本 → 他人 / 社会 / 环境 / 未来的自己
```

**属于这一家的旧机制：**

- **Externality｜外部性**：收益归一方，成本由另一方承担。
- **Cost Shifting｜成本转嫁**：更具体地说，当前 / 私人负担下降，成本被转给别人或未来。

**什么时候有用 / 不要硬套：**

- 有用：污染、垃圾、拥堵、公共资源过度使用、拖延、负债、家庭责任逃避。
- 不要硬套：如果成本其实完全由决策者自己承担，就不是外部性。
- 不要把所有公共问题都道德化为“个人自私”；有时是制度和设施让低成本选择不可得。

---

### 家族七：为什么大家都更努力，结果却越来越卷？

**它在解释什么：**
个体理性可能制造集体无效率；竞争升级、正反馈和负反馈，会让趋势加速、减速或反转。

**最基本的过程链：**

```text
升级：A 加码 → B 跟进 → 门槛上升 → 相对优势消失 → 继续加码
正反馈：X → Y → 更多 X
负反馈：X ↑ → 纠正反应 → X ↓
```

**属于这一家的旧机制：**

- **Escalation / Arms Race｜升级循环**：每个人都加码，结果整体没有进步，只是门槛越来越高。
- **Positive Feedback｜正反馈**：一个结果反过来加强原因，趋势越滚越大。
- **Negative Feedback｜负反馈**：一个变化引发纠正反应，趋势被压回去。

**什么时候有用 / 不要硬套：**

- 有用：内卷、加班竞争、学历通胀、补课竞赛、孤独的自我强化。
- 不要硬套：如果只是一个人努力，没有“别人跟进 / 门槛上升”，就不要说升级循环。
- 不要把所有竞争都写成内卷；竞争也可能带来进步。

---

### 家族八：为什么同样的东西换个人或场景就失效？

**它在解释什么：**
东西存在，不等于适合；需求、能力、入口、承载能力不匹配，都会让同样的方案失效。

**最基本的过程链：**

```text
A 存在，B 存在，但 A ≠ B
需求 > 承载能力
形式上有 ≠ 实际上够得到
```

**属于这一家的旧机制：**

- **Mismatch｜错配**：技能 ≠ 岗位需求；服务 ≠ 用户需要；教育 ≠ 劳动市场需求。
- **Capacity Gap｜承载不足**：需求超过现有能力。
- **Access Barrier｜可及性障碍**：形式上有，实际上够不到（距离、价格、年龄、技能、信息、设备等）。

**什么时候有用 / 不要硬套：**

- 有用：就业、数字鸿沟、医疗、养老、教育、公共服务。
- 不要硬套：如果只是“数量不够”，不要用错配；如果只是“人们不想用”，不要自动说成可及性障碍。
- 三者不同：错配是“对不上”，承载不足是“装不下”，可及性障碍是“够不到”。

---

### 家族九：事情接下来会怎么变？

**它在解释什么：**
变化不是一条直线；增长会饱和、收益会递减、新事物会扩散、落后者会追赶、制度会滞后、量变可能跨过阈值。

**最基本的过程链：**

```text
饱和：基数高 → 继续增长空间小 → 增速放缓
边际递减：投入 ↑ → 边际收益 ↓
扩散：早期采用者 → 更广人群 → 普及
追赶：低基数增长 > 高基数增长 → 差距缩小
滞后：A 在 t 时变化 → B 更晚调整
阈值：低于阈值效果有限 → 跨过阈值性质改变
```

**属于这一家的旧机制：**

- **Saturation｜饱和**：基数已经很高，继续增长空间变小，增速放缓。
- **Diminishing Returns｜边际递减**：投入继续增加，但边际收益下降。
- **Diffusion｜扩散**：从早期采用者走向更广人群。
- **Catch-up｜追赶**：低基数一方增长更快，差距缩小。
- **Lag｜滞后**：一个环节先变，另一个环节更晚才调整。
- **Threshold｜阈值**：低于某个点效果有限，跨过某个点发生质变。

**什么时候有用 / 不要硬套：**

- 有用： adoption 曲线、城乡差距、政策滞后、压力 / 保护 / 技术使用的临界点。
- 不要硬套：如果材料只有一个时间点，不要硬写“趋势”；如果增长慢，不要自动说“兴趣下降”，也可能只是基数高。
- 不要把“饱和”与“衰退”混为一谈；不要把“追赶”写成“领先者变差”。

## 五、机制使用纪律

### 1. 一条机制链胜过原因清单

通常：

> **1 条讲清楚 > 4 条点到为止。**

### 2. 一篇文章一般只需要 1–2 个机制

不要为了完整，扫描整个库。

### 3. 机制必须有中间过程

如果只是：

> A causes B

还不算真正解释。继续问：

> 中间发生了什么？

### 4. 机制不能超过材料支持

引用 `01_看材料.md` 的 Evidence Ceiling：

- 材料只显示同时发生 → 最多写“可能有关 / 可能有推动”；
- 材料没有提供因果证据 → 不要虚构机制；
- 可以提出合理解释，但要用与证据强度匹配的措辞。

### 5. 机制不是万能升级

普通题不需要机制，就不要用。

机制只在“解释不通”时出场，不是每篇作文的必经步骤。

## 六、机制和另外四个动作的关系

| 动作 | 回答的问题 |
|---|---|
| 看材料 | 发生了什么？ |
| 判关系 | A 与 B 是什么关系？ |
| 问价值 | 为什么值得？ |
| 找失灵 | 哪里没有实现原本目标？ |
| **机制** | **为什么会形成这种关系 / 价值 / 失灵？** |

所以机制通常是：

> **解释器**

不是第五种作文类型，也不是固定流程中的一步。

## 七、最简程序

```text
我知道现象，但解释不通？
↓
中间缺了哪一步？
↓
从“症状 → 机制”表找一个家族
↓
写成一条过程链
↓
这条链有没有超过材料？
↓
够解释就停
```
